# AsiBackbone Adopters

This file records public, permission-based evidence that people and
organizations use AsiBackbone packages, templates, samples, or learning
materials. It helps maintainers understand real adoption needs without implying
endorsement, certification, production readiness, or a support commitment.

## Recorded adopters

No adopters have opted into this public list yet.

When entries are accepted, they use this format:

| Adopter | Usage | Evidence | Since |
| --- | --- | --- | --- |
| Name or organization, with permission | Packages, template, evaluation, or learning path | Public link or maintainer-verified report | YYYY-MM |

## Add or update an entry

Use the [adopter report form](https://github.com/AsiBackbone/AsiBackbone/issues/new?template=adopter.yml)
to describe how you use the project. A public link is welcome but not required;
maintainers may record a report as privately verified when publishing the
underlying deployment or organization would be inappropriate.

The reporter must have permission to publish the submitted name, organization,
links, and usage summary. Do not include customer data, credentials, private
architecture details, or other sensitive information. Maintainers may edit a
summary for clarity and will confirm the final wording before adding it here.

To correct or remove an entry, open an adopter report and choose the applicable
request type. Removal does not require an explanation.

## What counts as adoption evidence

An entry may describe production use, a pilot or evaluation, a generated host,
a package integration, or substantial use of the Learning material. External
contributors are tracked through GitHub contribution history and may also opt
into this file when they use the project.

Repository stars, package downloads, automated dependency updates, and
maintainer-owned samples are useful signals but are not listed as verified
adopters by themselves.
